4. Software Description

4.1 CyberRMF Integrate provides the following core capabilities:

  • (a) Artifact management - interactive Security Control Traceability Matrix (SCTM), Plan of Action and Milestones (POA&M), Continuous Monitoring (CONMON), policy and procedure documents, and related compliance artifacts.
  • (b) Inventory tracking - asset inventory with NIST SP 800-53 control requirement mapping, native drag-and-drop floorplan layouts, and end-of-life tracking.
  • (c) Third-party integration - optional outbound connections to SIEM, antivirus / endpoint detection and response (EDR), and vulnerability management platforms configured by the Licensee.
  • (d) STIG validation - import and parsing of XCCDF benchmark files for Security Technical Implementation Guide compliance checks.
  • (e) Auditing - network diagnostics (ping, traceroute, DNS lookup) and cyber hygiene health dashboards.
  • (f) Workspace export and import - full workspace packaging as ZIP archives for transfer between users, organizations, or Security Control Assessors (SCAs).

4.2 CyberRMF Admin Tools provides the following capabilities:

  • (a) Ports, Protocols, and Services (PPS) generation - enumerates running processes and active network connections on target hosts.
  • (b) Installed software inventory - collects software lists from Windows (WMI/CIM) and Linux (package manager queries) systems.
  • (c) Encryption verification - checks BitLocker status (Windows) and block device encryption (Linux) on target hosts.
  • (d) Log collection - enumerates and exports Windows event logs and Linux system logs from remote systems.
  • (e) Active Directory user enumeration - queries AD for user accounts using PowerShell or LDAP.
  • (f) DNS spot check - performs forward and reverse DNS lookups to verify hostname and IP consistency against inventory records.
  • (g) Domain join verification - queries Active Directory for domain-joined computer objects.

4.3 Shared Workspace. Admin Tools writes scan results to the shared Workspace directory. Integrate reads these results to populate dashboards, reports, and artifact views. The two applications communicate exclusively through the shared file system and do not use inter-process communication, network sockets, or any external relay.

5. Admin Tools - Credentials and Elevated Privileges

5.1 Administrative Access Required. Admin Tools requires Windows domain administrator credentials or equivalent privileges to perform remote operations on target systems via Windows Management Instrumentation (WMI), Windows Remote Management (WinRM), and Secure Shell (SSH). The Licensee is solely responsible for ensuring that the credentials used have appropriate authorization for the systems being scanned.

5.2 Credential Handling. Credentials entered into Admin Tools are stored exclusively in application memory (the main process of the Electron runtime). Credentials are never written to disk, never transmitted to CyberRMF LLC or any third party, and are automatically cleared after ten (10) minutes of application inactivity or upon explicit user action. During active scan operations, credentials may be passed to child processes (PowerShell, SSH) via environment variables for the duration of the operation.

  • (a) CyberRMF Admin Tools does not retain, persist, or transmit user credentials beyond the active application session as described in Section 5.2;

  • (c) CyberRMF LLC shall not be held liable for any security incident, unauthorized access, data breach, or system compromise arising from the use of Admin Tools on systems the Licensee is not authorized to administer; and
  • (d) the Licensee is responsible for complying with all applicable organizational policies, regulations, and laws governing the use of privileged credentials and remote system administration.

5.4 Local System Modifications. Admin Tools includes an optional WinRM configuration helper that, with explicit User Account Control (UAC) approval, may modify the local machine's WinRM service settings, firewall rules, and TrustedHosts list. Admin Tools records the previous settings and offers an "Undo WinRM changes" action to restore them. The Licensee acknowledges that these changes affect the local system's security posture and accepts full responsibility for authorizing them and for restoring the previous configuration.

6. Third-Party Integrations

6.1 Outbound Connections. Integrate and Admin Tools can establish outbound network connections to Third-Party Services configured by the Licensee. These connections are initiated solely at the Licensee's direction using URLs and credentials provided by the Licensee. The Software does not expose an API, does not function as a network service, and does not accept inbound connections, with one exception: if the person running Admin Tools chooses Configure WinRM and approves the administrator prompt, Admin Tools turns on Windows Remote Management (WinRM) and PowerShell Remoting on that person's own device, which creates a WinRM listener and the Windows firewall rules for it, and adds the scan target to that device's WinRM trusted hosts. Admin Tools records the device's previous settings, and Undo WinRM changes restores them.

6.2 Supported Integrations. As of this version, Integrate and Admin Tools support connections to Splunk and ELK/OpenSearch for SIEM; Trellix ePO, CrowdStrike Falcon, Microsoft Defender for Endpoint, Symantec Endpoint Protection Manager (SEPM), VMware Carbon Black, and other endpoint protection platforms with a REST API for antivirus and endpoint protection; and Tenable.sc and Nessus for vulnerability management.

6.3 TLS Certificate Verification. Integrate and Admin Tools verify the TLS certificate of every Third-Party Service they connect to over HTTPS before it sends any data or credentials. A certificate that passes standard verification is accepted. If a certificate cannot be verified (for example, because it is self-signed, was issued by a certificate authority that the Software does not recognize, was issued for a different server name, or has expired), the Software closes the connection without sending anything and shows the certificate's details, including its SHA-256 fingerprint. The Licensee may then choose to trust that exact certificate for that server. After that, the Software accepts the trusted certificate for that server, and if the server presents a different certificate that cannot be verified, the Software refuses the connection until the Licensee reviews and trusts it. Trusted certificates are stored for each user on each device. The Licensee is responsible for confirming that a certificate belongs to the intended server before trusting it. Connections to a Third-Party Service configured with an http:// address are not encrypted.

6.4 SSH Host Key Verification. Admin Tools verifies the host key of every remote system it connects to over SSH, in the manner of OpenSSH's known-hosts file. Before a scan, Admin Tools reads the host key of each target that has no approved key on the device, without attempting to log in, and asks the person running the scan to approve the new hosts and their key fingerprints. Connections that send credentials accept only the approved key: a host that has not been approved, or whose key has changed, is refused before any credentials are sent. Approved host keys are stored for each user on each device and can be reviewed and removed in Admin Tools. The Licensee is responsible for confirming that a host key belongs to the intended system before approving it.

7. File System Access and Data Storage

7.1 File System Permissions. The Software requires permission to create, read, write, and delete files and directories within (a) the Licensee's designated Workspace directories and (b) the application's local data directory (Electron userData). The Licensee is responsible for ensuring that appropriate file system permissions are granted.

7.2 Local Data Storage. All application data - including inventory records, scan results, artifacts, configuration settings, and workspace metadata - is stored in the Licensee's Workspace directories and on the Licensee's device in JSON format and standard file structures.

7.3 Credential and License Encryption. API tokens, passwords, and keys for Third-Party Services are encrypted with the operating system's secure storage facility (Electron safeStorage, which uses DPAPI on Windows) and are stored for each user on each device, separately from the Workspace. They are not written to the shared Workspace, and each person who uses a shared Workspace enters their own tokens. If the operating system's secure storage is unavailable, tokens are not saved. The local license file is encrypted with the same facility when it is available. Scan results and general Workspace data are stored as plaintext JSON.

7.4 No Remote Storage. Apart from the licensing requests described in Section 3, and connections to Third-Party Services that the Licensee configures, no data is transmitted from the Software to CyberRMF LLC servers, cloud services, or any external party.

7.5 Workspace Locking. The Software uses cooperative file-based locking to prevent concurrent conflicting edits to the same Workspace. Lock files are stored in the Workspace's .cyberrmf directory and identify the active user by operating system username and hostname.

7.6 Activity Log. Each application keeps an Activity Log of actions taken in a Workspace, such as data saved or deleted, files added or removed, scans run, integrations used, and errors. Each entry records the time, the application and its version, and the operating system user name, domain, and computer name of the person who took the action. Entries are written to the Workspace's .cyberrmf directory, where other users of the Workspace can view them, and are chained so that later edits can be detected. Technical details of errors, such as stack traces, are kept only on the device where they occurred. Each application also records, once per launch, basic system details (the Windows version, application and runtime versions, memory and free disk space) and, if an application or one of its processes crashes, a crash dump file, which can contain memory contents from the time of the crash, unless an administrator has turned crash dumps off for the device. When crash dumps are turned off, the application records the crash without a dump and deletes any crash dumps it saved before. These are also kept only on the device; technical details of errors and crash dumps are deleted once they are fourteen (14) days old, the next time the application runs. The Activity Log is not transmitted to CyberRMF LLC.

7.7 Support Bundles. A user may choose to create a support bundle: a ZIP file, saved where the user chooses, containing system details, license status and the device's recent crash reports, including any crash dumps on the device unless an administrator has turned crash dumps off. Support bundles never contain Activity Log entries, Workspace file contents, saved credentials or the license key. The Software does not send support bundles anywhere; the user decides whether and how to share one. If a user sends a support bundle to CyberRMF LLC, CyberRMF LLC uses it only to investigate the reported problem.

8. Network Operations

8.1 Integrate Network Activity. Integrate performs local network diagnostic operations, including ICMP ping, traceroute, and forward and reverse DNS lookups, which the Software makes itself using the DNS servers configured on the device, for auditing and cyber hygiene assessment purposes.

8.2 Admin Tools Network Activity. Admin Tools performs targeted remote operations against hosts listed in the Licensee's inventory. These operations include WMI queries (TCP port 135 and dynamic RPC ports), WinRM sessions (TCP port 5985), and SSH connections (TCP port 22). Admin Tools does not perform subnet sweeps, port scanning of arbitrary hosts, or network discovery beyond the hosts explicitly listed in the inventory.

8.3 Log Collection. Admin Tools can copy Windows event log files (.evtx) and Linux system logs from remote hosts to a local directory selected by the Licensee. To collect Windows event logs, Admin Tools exports them on the remote host into a temporary folder it creates under that host's Windows Temp folder, copies them from there, and then deletes that folder; over WMI it starts the Windows event log utility (wevtutil.exe) on the remote host to do so. The Licensee is responsible for securing collected log data in accordance with organizational policies.

8.4 Licensing Traffic. The only connections the Software makes to CyberRMF LLC or its service providers are the license activation, re-validation, and deactivation requests described in Section 3.
